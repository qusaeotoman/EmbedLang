# Живой отчёт EmbedLang

Начат 2026-10-17. Формат — Markdown, будущий экспорт в PDF. Приложения
подготовлены с помощью ИИ как проверяемые технические материалы. Основные
авторские разделы остаются за студентами, как требует пользователь.

**Публичная source-редакция от 2026-10-18:** отчёт и audit ниже сохраняют хронологию
локальной разработки. Старые «не опубликовано»/«без коммита» относятся к моменту
этапа; актуальный scope публичного обновления, проверки и исключения перечислены
в [PUBLICATION_NOTES.md](../../PUBLICATION_NOTES.md). Локальные milestone hashes —
идентификаторы происхождения, не коммиты публичной Git-истории. Личные разделы
не заполнены, лицензируемые ограничения OLED не отменены публикацией отчёта.

- [REPORT.md](REPORT.md): структура академического отчёта и личные разделы.
- [APPENDICES.md](APPENDICES.md): факты, исходники, результаты и ограничения.
- [VERIFICATION.md](VERIFICATION.md): журнал выполненных проверок.
- [ASSIGNMENT_MAPPING.md](ASSIGNMENT_MAPPING.md): сверка с первичным PDF задания.
- [CODE_EXCERPTS.md](CODE_EXCERPTS.md): интересные исходные фрагменты с русскими пояснениями.
- [FINAL_COMPLIANCE_AUDIT.md](FINAL_COMPLIANCE_AUDIT.md): итоговая матрица,
  обязательные пробелы, вопросы CubeIDE/приёмки и приоритетный checklist сдачи.

## Обновление после каждого следующего этапа

1. Сохранить личные тексты студентов; не переписывать их как автоматически
   созданные разделы и не отмечать непроверенные пункты выполненными.
2. Добавить этап в приложение B: состояние, фактически изменённые компоненты,
   коммит только если он существует. Не обещать публикацию без разрешения.
3. В VERIFICATION.md записать дату отчёта о запуске, точную команду, результат,
   число проверок, необходимые зависимости и тип доказательства.
4. Не переносить старый успешный запуск как новый. Пропуски и блокировки
   указывать явно. Не выдавать конфигурационные/мок-тесты за VS Code Host-тесты.
5. Новое физическое наблюдение добавлять только по реальному сообщению
   пользователя или аппаратному свидетельству. Отделять дату сообщения от
   неизвестной даты измерения.
6. Перечислить новые ограничения и отличия полного локального проекта от
   публичного снимка. Не включать бинарники, логи, Flash-бэкапы, секреты и
   персональные машинные пути.
7. Оригинал задания идентифицирован: сверять ASSIGNMENT_MAPPING.md со слайдами
   10–15 и сохранять рабочие ID отличимыми от нумерации лектора. При уточнениях
   обновлять матрицу совместно со студентами, не выдумывая критерии/оформление.

Тесты расширения и компилятора не используют плату. Отчёт не утверждает,
что новый этап был испытан на STM32, если этого не происходило.
